# Hardening dan deployment

Status: fondasi diperkuat, bukan sertifikasi siap produksi. Modul aktif hanya autentikasi, inventori, stock count, adjustment dan posting. Receiving, issue, laporan dan ekspor BigSeller belum tersedia.

## Migrasi aman

Backup dan uji restore sebelum perubahan. Jalankan `npm run migrate` menggunakan DATABASE_URL role pemilik/migrasi. Produksi tidak menjalankan migrasi saat startup. Migrasi 003 menambahkan katalog, FK produk/batch, indeks, batas saldo dan larangan TRUNCATE tanpa mengubah ledger lama. SKU/batch historis disalin persis dan ditandai `legacy=true`; tidak di-trim/digabung karena mengubah identitas stok. Rekonsiliasi kode historis melalui transaksi pembalik yang disetujui; jangan UPDATE ledger. SKU baru dibuat Head melalui POST /api/products `{code,name,batches}`; kode baru dinormalisasi uppercase, input count wajib cocok katalog secara tepat. Batch tambahan untuk SKU lama saat ini melalui prosedur operator terkontrol.

Saldo per SKU/batch/lokasi dibatasi 2,147,483,647; audit saldo historis melampaui batas sebelum go-live. Count menerima 0 sampai 10.000 baris dengan body maksimal 4 MiB. Lebih besar memerlukan pemecahan lokasi/proses baru, bukan pemotongan snapshot. Inventori memakai limit (maksimal 1.000, default 200) dan offset; UI menyediakan halaman berikut/sebelumnya. Belum ada tabel saldo materialized atau pagination count list (200 terbaru).

## Deployment

Gunakan `docker-compose.production.yml`, bukan compose development. Tidak ada port database/API yang dipublikasikan. Bangun image; start postgres dahulu. DATABASE_URL runtime harus memakai `buymore_app`, bukan POSTGRES_USER. Dengan koneksi pemilik jalankan `node dist/migrate.js` di image backend, lalu jalankan `deploy/roles.sql` dan set password role memakai kanal aman (psql password prompt/secret manager). Role migrasi adalah pemilik schema yang terpisah dari role runtime; akun bootstrap PostgreSQL tidak digunakan API. Jangan memberi hak owner/superuser/BYPASSRLS ke runtime.

Provision Head pertama dengan koneksi pemilik: ADMIN_USERNAME, ADMIN_PASSWORD (minimal 16 karakter), ADMIN_WAREHOUSE dan `node dist/provision.js`. Perintah menolak jika Head sudah ada. Jangan gunakan seed development pada produksi. Provision Staff/Admin, membership dan lokasi menggunakan akses operator pemilik yang diaudit; UI administrasi pengguna belum tersedia. Jangan menyimpan rahasia di repo/log/shell history. Rotasi password memerlukan operator dan pencabutan sesi.

Pasang TLS ingress di depan web 127.0.0.1:8080. APP_ORIGIN harus tepat https://host (tanpa slash/path). Nginx internal memberi CSP, HSTS, frame denial dan nosniff, serta menimpa X-Forwarded-For. TRUSTED_PROXIES adalah daftar alamat peer API yang tepat (termasuk bentuk IPv4-mapped bila digunakan); tidak menerima wildcard/hop count. Tanpa konfigurasi header forwarded diabaikan. Pada ingress TLS tambahan, konfigurasi real_ip nginx hanya untuk alamat ingress terpercaya; jangan menerima header dari internet. Verifikasi IP aktual sebelum go-live, terutama saat proxy memakai alamat container dinamis. Healthcheck menguji DB. API memiliki timeout dan drain 20 detik, restart policy tetap diperlukan.

Jadwalkan `node dist/cleanup.js` setiap 15 menit dengan kredensial runtime. Job batch menghapus sesi expired/idle dan login counter kedaluwarsa. Receipt idempotensi tidak otomatis dihapus: penghapusan memungkinkan replay transaksi lama. Kebijakan arsip receipt memerlukan desain replay protection terpisah. Sesi maksimal 8 jam, idle 30 menit; POST /api/logout-all mencabut semua perangkat. Kunci retry UI bertahan selama komponen terbuka, tidak lintas reload browser.

## Bukti dan deployment gates

Regresi lokal memakai PGlite terisolasi, bukan database live. Docker tidak tersedia. PostgreSQL 18 ditemukan di Program Files (bukan PATH); cluster fixture baru pada loopback port 55439 berhasil menguji migrasi berulang, pemutusan koneksi idle nyata dengan pg_terminate_backend lalu recovery pool, 15 login gagal paralel (10 x 401, 5 x 429), 12 login sukses tanpa throttle, serta SELECT diizinkan dan UPDATE/TRUNCATE ledger ditolak role runtime. Cluster fixture dihentikan dan dihapus; database existing port 5432 tidak dimodifikasi. Sebelum go-live wajib uji PostgreSQL 17 multi-koneksi: login paralel, start/approve/post paralel, pg_terminate_backend koneksi idle, restart DB, timeout, hak role termasuk TRUNCATE, migrasi dari salinan data, image dan reverse-proxy TLS/header/CSP. Uji backup-restore dan load/retention dengan volume produksi.

H1 pool handler/timeout dan H2 failure-only throttle account 10/IP 100 dengan advisory lock diterapkan. Kegagalan disimpan walau respons 401; sukses tidak mengonsumsi limit. H3 FK katalog melindungi ledger. M1 memakai DomainError/SQLSTATE, M2 bulk sampai 10k/kosong, M3 read tanpa FOR UPDATE, M4 indeks/pagination inventori, M5 bulk submit/verify dan lookup linear. M5 konsolidasi semua transaksi autentikasi masih tersisa. M6 grants + truncate guards, M7 security_events/request-id/log aman, M8 FK katalog + quantity guard, M9 tes demo dikecualikan dari suite aktif, M10 formatter/typecheck/CI, M11 Docker/proxy/provisioning tersedia.

Batas tersisa: FK actor/warehouse historis belum dimigrasikan (identitas seed lama berupa teks), serial/UoM belum diimplementasikan; audit_events domain lama belum memuat request-id (security_events memuatnya). Recount tetap assigned Staff asli; penugasan ulang belum didukung dan harus ditangani melalui pembatalan + count baru yang diaudit, bukan edit ledger. Parameter scrypt tetap format lama untuk kompatibilitas; format hash rusak fail-closed. UI aktif diuji loading dan klien API, belum E2E semua interaksi. Tidak ada klaim bahwa seluruh finding sudah ditutup.
