# Catalog archive and initial stock

- The active application is `InspectionWorkspace` (imported by `frontend/src/main.tsx`).
- Admin can archive all active SKU from Master & impor. Confirmation explicitly covers every warehouse and SKU hidden by search. This is not deletion: products, ledger, inspection evidence and audit history remain.
- `POST /api/workspace/products/archive-all` requires Admin membership, an idempotency key and `{ "confirmation": "ARCHIVE ALL ACTIVE SKU" }`. One transaction locks active products and checks each SKU across all warehouses. Nonzero location/batch balances, pending inspections, active reservations, unfinished operation documents or unfinished counts abort the entire request. No subset is archived.
- The inspection SKU chooser shows official total PCS across all locations/batches in the selected warehouse. Review shows current official PCS for the inspection's exact product/location/batch, separately from observed quantity and the historical submission snapshot. Values refresh when workspace data reloads; they are not a live subscription. Unavailable catalog data is not displayed as zero.
- Initial stock import requires explicit MASTER quantity mapping and confirmation. Quantity multiplied by the selected PCS conversion is appended to the ledger at the chosen location, never used to overwrite history. Eligibility is per SKU + selected warehouse: any prior ledger row for that SKU in that warehouse blocks opening stock, even with a zero balance or a different destination location. Other SKU history does not block a fresh SKU; the entire warehouse need not be empty. The destination location lock and per-SKU ledger history guard remain in place. If any imported SKU is ineligible, the entire import rolls back without overwriting existing history.
- The repository supplies PO and SR templates, not a verified master stock export. Therefore no stock header aliases are invented or automatically selected. Select the physical official stock column, not available/reserved/purchase quantities, and verify the source warehouse and units. PO/SR remain master-only. Automatic quantity recognition/default initial-stock mode requires a genuine documented MASTER sample before it can be enabled safely.
- No database migration is required for these changes.
